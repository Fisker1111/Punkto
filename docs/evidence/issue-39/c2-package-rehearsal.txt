C2 package rehearsal — tooling rehearsal on a FOUNDER-CONTROLLED host
This is NOT the C2 independence proof and NOT independent custody.
The host used here is founder-controlled, so it cannot satisfy Issue #39's
independent-operator requirement. What this file demonstrates is only that the
onboarding package's commands work end to end: import, serve from the node's own
origin, survive a node restart, survive a tar backup -> restore into a fresh data
directory, and are reachable while founder origins are blocked at the client.

Environment
- Host class: founder-controlled (Hermes worker host). Not an independent operator.
- Node: generic Punkti node started from the repository source (`python3 -m punkti_node`),
  equivalent to the container's `/app/punkti_node` package. Docker was unavailable on the
  rehearsal host, so the container entrypoint path was not executed.
- Python: 3.14.9 (repository targets 3.12; 3.12 was unavailable).
- Origin blackout: client-side only, via `scripts/qa/independent_origin_block_proxy.py` and,
  separately, `curl --resolve`/`--connect-to` blackholing.
