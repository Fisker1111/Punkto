How to run this test (volunteer with a phone)

  1. Print this sheet at 100% / actual size — do not use “fit to page” or “shrink”, which changes the module size and invalidates the test. Print every page of the sheet.
  2. Scan with your phone's stock camera app. Note the app name and version.
  3. For code B (BRQ1D, 2693 raw binary bytes) you need a scanner app that can return raw binary bytes. A text-only scanner will corrupt or refuse this payload — that is a tooling limitation, not a QR failure.
  4. Record for each code: app name, distance (cm), angle, lighting condition, and success / failure.
  5. Compare the recovered bytes' SHA-256 against the value printed next to the code. If your app can only export text, export hex and use the --bytes-hex option of the offline verifier.

Offline verification

Fully offline; no network, no Punkti node, no DNS:

python3 scan_verify.py --self-test          # against the local test artifacts
python3 scan_verify.py scan.png                      # a photo of the printed sheet
python3 scan_verify.py scanned_bytes.hex            # raw bytes exported by your app

A pass means: the decoded bytes match the printed SHA-256, and the payload reconstructs the expected TEST IdentityID with the unchanged Layer-4 PQ code. It does not mean the physical design is validated for real identities, and for code B it does not prove possession or current authority.
