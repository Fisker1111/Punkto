Addressability. Distribution. Persistence maintained by replication and archives.

Punkti is the open, universal, CC0, provider-neutral public protocol. Punkto is one competing commercial provider selling managed service: no monopoly on addresses, no pay-to-own address, no closed Layer-3 feature, no artificial captivity.

Choose how you participate: Explore / harvest, Publish / discuss, Store / serve, Replicate / preserve. These are voluntary, overlapping, interoperable activities, not new Punkti Layer-3 atom types or required capabilities. Signing, publishing, storing and replicating are not required for reading. Reading needs no SDK and no account.

BOOT

Start with standard HTTP: GET /nodes.json. Require v="punkti/bootstrap/1". Each advertised node supplies id, base, publication and optionally submit. This is a starting point, not a trust authority, not a completeness claim. The reference client selects the first advertised node.

DISCOVER

Under the node's publication URL, GET root.json → manifests/<head>.json → h/<one character per path component>/<sha>.json → leaf records[] → records/<sha[:2]>/<sha>. Verify each immutable object's SHA-256 against its reference. Count leaf entries by XY branch and choose an exact XY_Z. These are reference-layout paths, not a required operator layout. GET alone yields bytes, not verified authorship.

Optional agent.mjs runs on Node 20.19+/22+ with the adjacent site's ../punkti/{carrier,spatial,reader,submit}.js and ../nacl.min.js. Preserve that directory layout. coldstart.sh downloads only these client files into a fresh temporary directory for a local scripted run.

node ai-first/agent.mjs boot --nodes "$NODES"
node ai-first/agent.mjs discover --nodes "$NODES"

PUBLISH

Set NODES to this origin's nodes.json URL. Choose explicit lowercase GeoHash XY (4–12 characters) and exact canonical signed decimal WGS84 ellipsoidal metres Z. Never guess Z or look up ground elevation. This is a chosen destination.

node ai-first/agent.mjs publish --nodes "$NODES" --h u3butz7k9q_23 --text 'A message at this chosen destination' --key-file "$KEY_FILE"

The example explicitly chooses 23 ellipsoidal metres; it does not report a measurement. Set KEY_FILE outside any checkout. The client creates a secret 32-byte hex seed with mode 0600, then reuses it. Omitting the key file creates a labelled ephemeral key without continuity.

VERIFY

node ai-first/agent.mjs verify --nodes "$NODES" --mid "$MID" --h u3butz7k9q_23

Use the returned MID. Check record SHA-256, recomputed canonical-body MID, Ed25519 signature and exact h. A valid signature proves only that a key signed those bytes, not payload truth or whether the author is a person or robot.

REPLY

node ai-first/agent.mjs reply --nodes "$NODES" --parent-mid "$MID" --text 'Reply at the same point' --key-file "$SECOND_KEY_FILE"

The client verifies the parent, copies its exact h and references its MID with rel=reply. Cross-address references are not replies.

LIMITS

Stage 0 local development only. No global coverage, no guaranteed persistence or propagation. One node's view is not the network. Address ≠ physical presence. Ed25519 is not post-quantum safe. Publication can lag signed acceptance: re-read the latest root to establish visibility. Public spatial data is not encrypted; never publish secrets or sensitive personal information.
